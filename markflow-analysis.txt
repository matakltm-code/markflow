2. MOTIVATION & OBJECTIVE
-------------------------------------------------------------------------------
MarkFlow was created to solve critical friction points in document editing and live rendering workflows. Traditional Markdown editors often suffer from input latency, heavy UI clutter, clunky preview scroll mismatches, or poor mobile rendering capabilities.

The core objective of MarkFlow is to provide a modern, high-performance, distraction-free Markdown Editor and Renderer built with React and TypeScript. Key motives include:
- Zero-Latency Input & Live Synchronization: Offering instant visual feedback with split-pane synchronized scrolling without compromising editor responsiveness.
- Seamless Visual Diagramming: Native support for Mermaid.js diagrams directly within standard Markdown code blocks (`mermaid`).
- Lightweight & Portable Architecture: Eliminating heavy global state frameworks in favor of React hooks and direct DOM manipulation for maximum speed and simplicity.
- Cross-Platform Accessibility: Providing an adaptable UI that seamlessly switches between a dual-pane desktop workstation layout and a mobile tabbed interface.

Architectural Pattern:
- Component-Based Decoupled Architecture: Clean separation into `components/editor`, `components/preview`, `components/ui`, `hooks`, and `utils`.
- Unidirectional Data Flow with Ref-Based Hooks: Raw Markdown state resides at the root (`App.tsx`), while synchronized scrolling uses React `useRef` hooks to interact directly with DOM nodes, preventing unnecessary React re-render cycles.
- Dynamic Theme Engine: Root CSS variable swapping controlled via top-level HTML element classes (`light`, `dark`, `theme-slate`), mapped directly to Tailwind utility tokens.

5. COMPLEX CHALLENGES & ARCHITECTURAL HIGHLIGHTS
-------------------------------------------------------------------------------
1. Bi-Directional Lock-Protected Scroll Synchronization (`useScrollSync.ts`):
   - Challenge: Syncing scrolling between two independent scrollable containers (`textarea` and preview `div`) can cause infinite feedback loops where scrolling element A triggers element B, which then triggers element A back.
   - Solution: Implemented a custom React hook `useScrollSync` using `isScrollingRef` as a temporary scroll lock ('editor' | 'preview' | null). When element A scrolls, the lock is engaged, calculating relative percentage `scrollTop / (scrollHeight - clientHeight)` and applying it to element B. A debounced timeout releases the lock once scrolling stops.

2. Custom Mermaid.js Syntax Parsing & Asynchronous SVG Injection (`MermaidViewer.tsx`):
   - Challenge: Intercepting Markdown code blocks, validating diagram syntax without throwing unhandled React rendering errors, and rendering SVG asynchronously.
   - Solution: Extended `react-markdown` components mapping to catch `language-mermaid` blocks and delegate rendering to `<MermaidViewer />`. The component uses `mermaid.parse(code)` for pre-validation prior to calling `mermaid.render()`. Unique dynamic IDs are generated per instance to avoid DOM collisions, and clean unmount guards (`isCurrent` flag) prevent race conditions during rapid editor keystrokes.

3. Dynamic Multi-Theme Token Architecture (`index.css` & `Toolbar.tsx`):
   - Challenge: Supporting full dark/light/slate themes with Tailwind CSS v4 without introducing runtime CSS-in-JS dependencies.
   - Solution: Utilized Tailwind v4 `@theme` variables mapped to semantic CSS custom properties (`--color-background`, `--color-primary`, `--color-surface-container`, etc.). `Toolbar.tsx` toggles root classes (`light`, `dark`, `theme-slate`), instantly remapping color definitions across the application without forcing component re-mounts.

4. Formatted DOM-to-PDF Conversion Engine (`exporters.ts` & `PreviewPane.tsx`):
   - Challenge: Converting raw React/HTML rendered Markdown preview structures into multi-page PDF documents while preserving fonts, padding, and layout.
   - Solution: Wrapped preview output inside a dedicated `#pdf-export-content` container with standard print boundaries. `exportToPDF` configures `html2pdf.js` with `html2canvas` (scale: 2, CORS enabled) and `jsPDF` (A4 format, portrait) to produce crisp vector-like output directly in the browser without server dependencies.
